# Архитектура проекта НейроПульс

## Общая схема

Проект построен по классической клиент-серверной архитектуре:

```
┌──────────────────┐       HTTP/JSON        ┌──────────────────┐
│  Flutter-клиент  │  ◄──────────────────►  │  FastAPI Backend  │
│  (мобильное      │                        │  (Python 3.11)    │
│   приложение)    │                        │                   │
└──────────────────┘                        └────────┬─────────┘
                                                     │
                                            ┌────────┴─────────┐
                                            │                  │
                                    ┌───────▼──────┐   ┌──────▼───────┐
                                    │ PostgreSQL   │   │ MOEX ISS API │
                                    │ (хранилище)  │   │ (котировки)  │
                                    └──────────────┘   └──────────────┘
```

## Компоненты

### Flutter-клиент

Мобильное приложение на Flutter с Material 3 дизайном. Управление состоянием — через пакет Provider (паттерн ChangeNotifier).

Структура слоёв:
- **models/** — простые Dart-классы для данных (Stock, Portfolio, Prediction и т.д.)
- **providers/** — бизнес-логика и управление состоянием
- **screens/** — UI-экраны и виджеты
- **services/** — HTTP-клиент для взаимодействия с backend
- **data/** — мок-данные для разработки и демо-режима

Навигация — одноуровневая: LoginScreen → MainScreen (с TabBar из 4 вкладок) → StockDetailScreen.

### Python Backend

REST API на FastAPI. Основные обязанности:
- Выдача прогнозов цен (LSTM-модель)
- Хранение и выдача исторических котировок
- Сбор данных с Московской биржи
- Приём CSV-файлов с фундаментальными данными

Структура слоёв:
- **main.py** — определение FastAPI-приложения и эндпоинтов
- **database/** — SQLAlchemy-модели и подключение к PostgreSQL
- **services/** — внешние сервисы (MOEX API, CSV-импорт, кэш)
- **ml/** — машинное обучение (препроцессор, LSTM-модель, пайплайн обучения)

### База данных

PostgreSQL 16 (через Docker). Четыре таблицы:
- `stock_data` — дневные котировки OHLCV
- `fundamental_data` — квартальные финансовые показатели
- `macro_data` — макроэкономические индикаторы
- `predictions` — сохранённые прогнозы модели

Подробнее — в [схеме базы данных](database-schema.md).

### ML-модель

LSTM-нейросеть на TensorFlow/Keras. Принимает последовательность из 60 дней (17 признаков на каждый день), выдаёт прогноз цены закрытия. Модели обучаются отдельно для каждого тикера.

Подробнее — в [документации ML-модели](ml-model.md).

## Потоки данных

### Прогнозирование (основной сценарий)

1. Пользователь открывает страницу акции в приложении
2. Flutter отправляет POST-запрос на `/predict` (тикер + период)
3. Backend проверяет кэш — если прогноз свежий, возвращает его
4. Если кэш пуст — загружает обученную LSTM-модель с диска
5. Загружает последние 60 дней данных из PostgreSQL
6. Рассчитывает технические индикаторы, нормализует
7. Прогоняет через модель, получает прогноз
8. Сохраняет прогноз в БД и кэш, возвращает клиенту

### Обновление данных

1. Администратор отправляет POST на `/admin/update_moex`
2. Backend запрашивает котировки по каждому тикеру через MOEX ISS API
3. Новые записи (которых ещё нет в БД) сохраняются в таблицу `stock_data`
4. Аналогично — загрузка CSV через `/admin/upload_csv`

### Обучение моделей

Выполняется вручную через скрипт `ml/trainer.py`:
1. Загрузка данных из PostgreSQL для каждого тикера
2. Расчёт технических индикаторов
3. Нормализация и формирование последовательностей
4. Разбиение на train/val/test (70/15/15)
5. Обучение LSTM с EarlyStopping
6. Сохранение модели и препроцессора на диск

## Текущие ограничения

- Flutter-клиент работает на мок-данных, интеграция с backend частичная
- Нет аутентификации на backend (эндпоинты открыты)
- Прогнозы не защищены от переобучения — мало данных для полноценной оценки
- Нет автоматического обновления данных (cron/scheduler)
- Одна LSTM-модель на тикер, нет ансамблей или альтернативных подходов
