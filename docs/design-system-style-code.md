# Дизайн-система и стиль продукта (для дизайнеров, художников, фронтенда)

## 1) Цель документа

Этот документ фиксирует единый визуальный и продуктовый язык приложения, чтобы:
- дизайн не расползался между экранами;
- разработка шла по стабильным UI-контрактам;
- любой новый экран выглядел как часть одной системы.

## 2) Продуктовый образ бренда

### Характер продукта

- Спокойный, собранный, профессиональный.
- Обучающий, но не "школьный".
- Технологичный, но без агрессивного "трейдерского неона".
- Доверительный, без обещаний доходности.

### Тон интерфейса (microcopy)

- Говорим просто и по делу.
- Не используем формулировки "гарантия", "точный прогноз", "заработок".
- Предпочтительные слова: "оценка", "сценарий", "вероятность", "учебный результат".

## 3) Цветовая система (Design Tokens)

## Базовая палитра

- `color.primary.500 = #1E5EFF` (основной синий)
- `color.primary.700 = #1745C6` (акцент при нажатии)
- `color.success.500 = #12B76A` (рост, успех)
- `color.warning.500 = #F79009` (внимание)
- `color.error.500 = #F04438` (ошибка, просадка)
- `color.neutral.900 = #101828`
- `color.neutral.700 = #344054`
- `color.neutral.500 = #667085`
- `color.neutral.200 = #EAECF0`
- `color.neutral.100 = #F2F4F7`
- `color.bg.base = #F8FAFC`
- `color.surface = #FFFFFF`

## Финансовые статусы

- Рост цены: `#16A34A`
- Падение цены: `#DC2626`
- Нейтрально: `#475467`

Правило: цвет никогда не должен быть единственным носителем смысла, всегда дублируем знаком или подписью.

## 4) Типографика

Рекомендуемый шрифт: `Inter` (fallback: `Roboto`, `SF Pro Text`).

### Шкала

- `display`: 32 / 40 / 700
- `h1`: 26 / 34 / 700
- `h2`: 22 / 30 / 600
- `h3`: 18 / 26 / 600
- `body.l`: 16 / 24 / 400
- `body.m`: 14 / 22 / 400
- `caption`: 12 / 18 / 500
- `mono`: 13 / 20 / 500 (для тикеров, чисел, процентов)

## 5) Сетка, отступы, радиусы

- Базовый шаг: `8px`.
- Контейнер экрана: горизонтальный padding `16px`.
- Вертикальные интервалы между секциями: `24px`.
- Радиусы:
  - карточки: `12px`
  - поля ввода: `10px`
  - кнопки: `10px`
  - модальные окна: `16px`

## 6) Компонентная библиотека (обязательный минимум)

### Кнопки

- `PrimaryButton` (заливка primary)
- `SecondaryButton` (контур)
- `GhostButton` (текстовая)
- Состояния: default / pressed / disabled / loading

### Поля ввода

- `TextField` с label, helper, error state.
- Маски для валюты и процентов.

### Карточки

- `AssetCard` (тикер, цена, % изменения, мини-график)
- `ScenarioCard` (название сценария, сложность, ожидаемая длительность)
- `LessonCard` (урок, прогресс, CTA)

### Навигация

- Нижний таб-бар (4 раздела).
- На детальных экранах единый `AppBar` без визуального шума.

### Графики

- Линейный график: толщина 2px.
- Свечи: бычья/медвежья палитра согласно финансовым статусам.
- Сетка и подписи не должны конкурировать с основными данными.

## 7) Иконографика и иллюстрации

- Иконки: outline-стиль, единая толщина 1.75-2.0.
- Иллюстрации: векторные, умеренно минималистичные, без "крипто-глэма".
- Изображения сценариев кризисов: нейтральные и образовательные, без драматизации.

## 8) Motion и поведение интерфейса

- Длительность базовой анимации: 160-220ms.
- Curve: `easeOutCubic` для появления, `easeInOut` для переходов.
- Не использовать сложные анимации на каждом действии.
- Анимация награды/XP — только в ключевых моментах.

## 9) Accessibility (A11y)

- Минимальный контраст текста: WCAG AA.
- Минимальный размер touch-target: 44x44.
- Не меньше 2 каналов обратной связи: цвет + текст/иконка.
- Поддержка системного масштабирования шрифта.

## 10) Готовые UI-правила для фронтенда (design-code contract)

### Naming convention для токенов

- `color.<group>.<level>`
- `space.<n>`
- `radius.<size>`
- `font.<role>`

Пример:
- `space.1 = 4`
- `space.2 = 8`
- `space.3 = 12`
- `space.4 = 16`
- `radius.card = 12`
- `radius.input = 10`

### Контракты для Flutter

- Любой новый экран собирается из существующих токенов.
- Запрещено вносить "магические" цвета и отступы в виджет напрямую.
- Тема хранится централизованно в одном месте (`app_theme.dart` + `design_tokens.dart`).

### Контракты для Figma

- Один файл дизайн-системы (tokens + components).
- Каждый компонент имеет варианты (state variants).
- Перед передачей в разработку обязателен checklist: states, empty/error/loading.

## 11) Визуальные анти-паттерны (запрещено)

- Неоновые цвета в базовом потоке обучения.
- Избыточные градиенты на каждом экране.
- Больше двух акцентных цветов на одном экране.
- Текст "капслоком" для важных метрик.
- Лишние финансовые термины без объяснения для новичка.

## 12) Структура экранов (рекомендуемый каркас)

### Dashboard

1. Верх: прогресс обучения + текущий уровень.
2. Центр: блок "сегодняшняя задача".
3. Низ: портфель, топ активов, быстрый переход в симулятор.

### Акция/инструмент

1. Тикер + цена + изменение.
2. График с переключением периода.
3. Блок "вероятностная оценка модели".
4. CTA: "потренироваться в сценарии".

### Сценарий

1. Контекст (что произошло на рынке).
2. Цель пользователя.
3. Шаги сценария и решения.
4. Итог: что было сделано хорошо/плохо.

## 13) Артефакты, которые должна подготовить дизайн-команда

1. Figma-файл `00-Design-System` (tokens + components).  
2. Figma-файл `01-Product-Flows` (основные user flows).  
3. UI Kit для разработчиков (экспорт спецификаций).  
4. Гайд по иллюстрациям и иконкам.  
5. Библиотека пустых/ошибочных/загрузочных состояний.

## 14) Что считать "дизайн готов"

- Все базовые экраны покрыты компонентами.
- Для каждого экрана есть empty/loading/error/success состояния.
- Цвета, отступы, типографика строго по токенам.
- Frontend может собирать экраны без ручного "дорисовывания решений".
