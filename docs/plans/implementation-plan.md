# План реализации: 4-месячный акселератор

Детальный план разработки проекта «Пре-Брокер» в формате стартап-акселератора. Рассчитан на студенческую команду из 5 человек.

---

## Ключевые решения

Ниже — сводка принятых решений по ключевым вопросам проекта.

### Клиентская часть

| Вопрос | Решение |
|---|---|
| Веб-версия | Нет на MVP. Только мобильное приложение. Flutter Web — после привлечения инвестиций |
| Платформы | Android first. iOS — к Demo Day #2 (через TestFlight) |
| Оффлайн-режим | Да для уроков (Hive/Isar). Симулятор — только онлайн |
| Графики | fl_chart для линейных + CustomPainter для свечей. Syncfusion не используем из-за лицензии |
| Тёмная тема | Да, она основная. Светлая — опция |
| Push-уведомления | Да, через Firebase. Напоминание об обучении, ежедневный челлендж, сценарий дня |

### Машинное обучение

| Вопрос | Решение |
|---|---|
| Горизонт прогноза | Дневной и недельный |
| Realtime-инференс | Нет. Пакетные предрасчёты ночью (cron, 03:00 МСК) |
| LSTM vs Transformer | LSTM для MVP. Transformer — эксперимент на месяц 3-4 |
| A/B-тест моделей | Нет. Оффлайн-сравнение в MLflow/W&B, деплоим лучшую |
| Допустимая ошибка | Directional accuracy ≥ 55%. MAE ≤ 5% на дневном горизонте |
| RL-агент | Нет на MVP. После акселератора. На MVP — бенчмарк «купи и держи индекс» |

### Данные

| Вопрос | Решение |
|---|---|
| Глубина истории | 2010–2024 для обучения LSTM. Для сценария «дефолт 1998» — отдельный набор |
| Тиковые данные | Нет. Дневные свечи (MVP), часовые — для продвинутых сценариев |
| Тикеры | Топ-30 по ликвидности MOEX + 5 ETF |
| Обработка данных | Только backend. Клиент получает готовое через API |
| Обновление | Раз в сутки после закрытия торгов (19:00 МСК) |

### Геймификация и бизнес

| Вопрос | Решение |
|---|---|
| Монетизация | Freemium. Бесплатно на этапе акселератора. Free / Pro (299 руб.) / Premium (599 руб.) |
| Социальные функции | Глобальный лидерборд + профили. Группы — после акселератора |
| Мультиплеер | Нет. Асинхронные соревнования (все проходят один сценарий недели) |
| Реферальная система | Да, простая. Уникальный код, +100 XP обоим |
| Адаптивная сложность | Упрощённая: if/else правила (провалил тест → повторить, всё на 90%+ → пропустить) |

### Инфраструктура и безопасность

| Вопрос | Решение |
|---|---|
| Хостинг | Yandex Cloud (грант для стартапов). Fallback: Timeweb VPS от 500 руб./мес |
| Персональные данные | ФЗ-152 compliance. Минимум данных: email, хеш пароля, прогресс. Серверы в РФ |
| SLA | 99% uptime. Мониторинг: UptimeRobot + Sentry (бесплатно) |
| CI/CD | GitHub Actions с первого дня. Push → тесты → сборка → деплой |
| Крипто | Нет в ближайший год. Архитектурно не закрываем возможность |
| Интеграция с брокером | Post-MVP. Через Tinkoff Invest API (показ реального портфеля рядом с учебным) |
| Чат-бот | Да, на месяц 3-4. Rule-based, keyword matching по базе из 200 вопросов |
| Локализация | Только русский. Код с l10n (Flutter intl) для будущей локализации |
| Real-time данные | Нет для MVP. Дневные данные бесплатны и достаточны |

## Методология разработки

**Kanban + двухнедельные спринты** (гибридный подход).

Почему не чистый Scrum: нет full-time команды (студенты учатся), нет отдельного product owner. Почему не чистый Kanban: нужны дедлайны (Demo Day), нужна предсказуемость.

- Kanban-доска в GitHub Projects
- Спринты по 2 недели с планированием и ретроспективой
- Синхронизация 2 раза в неделю по 30 минут (Telegram/Discord)
- Async-общение в Telegram-чате команды

### Инструменты (все бесплатные)

| Задача | Инструмент |
|---|---|
| Управление проектом | GitHub Projects |
| Код | GitHub (приватный репо) |
| CI/CD | GitHub Actions (2000 мин/мес) |
| Дизайн | Figma (бесплатно для студентов) |
| Документация | Notion (бесплатно для студентов) |
| Коммуникация | Telegram |
| ML-эксперименты | Weights & Biases |
| Мониторинг | Sentry + UptimeRobot |
| Аналитика | Firebase Analytics |

## Спринты

### Этап 1: Недели 1-8 → Demo Day #1

**Спринт 1 (нед. 1-2): Скелет**
- Рабочий прототип с навигацией и авторизацией
- Скрипт загрузки данных MOEX ISS
- Wireframes всех экранов в Figma
- CI/CD на GitHub Actions

**Спринт 2 (нед. 3-4): Обучение**
- 8 уроков + 4 теста (Месяц 1 учебной программы)
- Экраны уроков и тестов в Flutter
- Первый LSTM-прототип в Colab

**Спринт 3 (нед. 5-6): Графики и симулятор**
- Свечной график (CustomPainter)
- Базовая торговля: покупка/продажа, портфель
- LSTM v1 обучен на 10 тикерах

**Спринт 4 (нед. 7-8): Полировка к Demo Day #1**
- Dashboard, лидерборд, анимации
- Интеграция LSTM-прогнозов в API
- Тестирование на 3-5 устройствах

**Результат Demo Day #1:**
- Работающее Android-приложение
- 16 уроков, 8 тестов, 30+ тикеров
- Свечной график + базовая торговля
- LSTM-прогноз (directional accuracy ≥ 52%)
- XP и лидерборд

---

### Этап 2: Недели 9-17 → Demo Day #2

**Спринт 5 (нед. 9-10): Сценарии и события**
- 5 исторических сценариев (санкции, нефть, COVID, бычий рынок)
- Система событий (всплывающие новости в timeline)
- LSTM v2: кризис-детектор

**Спринт 6 (нед. 11-12): Геймификация**
- 20 достижений с условиями
- Ежедневные челленджи
- Whale detector (ML)
- Профиль пользователя со статистикой

**Спринт 7 (нед. 13-14): Бета**
- Закрытая бета: 30-50 тестеров
- Firebase App Distribution
- Push-уведомления
- Реферальная система

**Спринт 8 (нед. 15-17): Финализация**
- Все 48 уроков
- 10 стабильных сценариев
- Финальный экзамен + сертификат
- Публикация в Google Play
- Питч-дек для инвесторов

**Результат Demo Day #2:**
- Приложение в Google Play
- 48 уроков, 24 теста, 10 сценариев
- 3 ML-модели (цена, кризис, сентимент)

## Управление рисками

| Риск | Вероятность | Что делаем |
|---|---|---|
| LSTM accuracy < 50% | Средняя | Используем как генератор реалистичных цен, а не как прогнозиста |
| MOEX ISS API упадёт | Низкая | Локальный кэш исторических данных. Fallback на Finam |
| Не хватает контента | Средняя | Приоритезируем первые 2 месяца. Остальное — «Скоро» |
| Участник уходит | Высокая | Перекрёстное обучение, документация, bus factor ≥ 2 |
| Не успеваем к Demo Day | Высокая | Убираем сентимент-модель и whale detector, фокус на ядре |
| Google Play отклоняет | Средняя | Проверяем политики заранее, добавляем дисклеймеры |
| Сервер не выдерживает | Низкая | 50 пользователей = ~5 RPS, любой VPS справится |
