# Возможные улучшения проекта

Ниже — конкретные направления доработки проекта, исходя из текущего состояния кода. Разделены по приоритетам: сначала то, что закроет основные пробелы, затем — расширение функциональности.

---

## Приоритет 1: Закрытие пробелов (что нужно доделать)

### 1.1. Подключить Flutter к реальному backend

Сейчас приложение работает целиком на мок-данных. Провайдеры (`StocksProvider`, `PortfolioProvider`) берут данные из `mock_data.dart`, хотя сервис `MlApiService` уже написан.

Что нужно:
- В `StocksProvider` заменить инициализацию из мок-данных на вызов `MlApiService.getHistory()` и `MlApiService.predict()`
- Добавить обработку ошибок сети (нет интернета, сервер недоступен)
- Сделать fallback на мок-данные, если backend недоступен (чтобы демо-режим сохранился)
- Вынести URL backend в конфигурацию (сейчас захардкожен в сервисе)

### 1.2. Аутентификация

На backend нет никакой защиты. Административные эндпоинты (`/admin/upload_csv`, `/admin/update_moex`) доступны всем.

Что нужно:
- Добавить JWT-аутентификацию на backend (FastAPI + python-jose)
- Реализовать регистрацию и вход на backend
- Связать `AuthProvider` в Flutter с реальным API вместо заглушки
- Защитить административные эндпоинты (middleware или Depends)

### 1.3. Автоматическое обновление данных

Сейчас обновление котировок запускается вручную через curl. Для рабочего приложения это неприемлемо.

Что нужно:
- Добавить планировщик задач (APScheduler или Celery) — обновление с MOEX каждый день в 19:00 МСК
- Автоматическое переобучение модели раз в неделю/месяц при накоплении новых данных
- Уведомление администратора при сбоях сбора данных

### 1.4. Улучшить доверительный интервал прогноза

Сейчас доверительный интервал — фиксированные ±10% от прогноза. Это не отражает реальную неопределённость модели.

Варианты:
- Monte Carlo Dropout: делать несколько прогнозов с включённым Dropout, считать стандартное отклонение
- Квантильная регрессия: обучить модель предсказывать не одно значение, а квантили (10%, 50%, 90%)
- Хотя бы калибровать интервал по ошибке на тестовом наборе

## Приоритет 2: Улучшение качества

### 2.1. Расширить признаки ML-модели

Сейчас модель использует только ценовые данные и технические индикаторы. В базе уже есть таблицы `fundamental_data` и `macro_data`, но они не подключены к модели.

Что добавить:
- Макропоказатели: цена нефти, курс доллара, индекс MOEX, ставка ЦБ (из таблицы `macro_data`)
- Фундаментальные данные: выручка, EBITDA, чистая прибыль (из `fundamental_data`, интерполированные до дневных)
- Календарные признаки: день недели, месяц, близость к дате отсечки дивидендов

### 2.2. Сравнение с другими моделями

Одна LSTM — это базовый подход. Для объективной оценки нужно сравнить с:
- Простая baseline: "цена завтра = цена сегодня" (наивный прогноз)
- ARIMA/SARIMA — классическая модель временных рядов
- XGBoost/LightGBM на тех же признаках
- Transformer-based модель (например, Temporal Fusion Transformer)
- Ансамбль из нескольких подходов

### 2.3. Улучшить UI/UX приложения

- Добавить тёмную тему (сейчас только светлая)
- Pull-to-refresh на списке акций
- Skeleton-загрузка вместо спиннера
- Расширить график: свечной (candlestick) вместо линейного, масштабирование, выбор периода
- Показать исторические прогнозы — насколько модель ошибалась раньше

### 2.4. Полноценные тесты

Сейчас тесты покрывают основные сценарии, но не покрывают edge-cases.

Что добавить:
- Тесты Flutter-виджетов (widget tests)
- Integration tests для Flutter (запуск на эмуляторе)
- Тесты API с авторизацией (когда она появится)
- Нагрузочное тестирование (locust или k6) — хотя бы базовое
- CI/CD: запуск тестов при push через GitHub Actions

## Приоритет 3: Новая функциональность

### 3.1. Геймификация и обучение

Добавить обучающий модуль:
- Уроки по основам инвестирования (что такое акция, дивиденд, P/E и т.д.)
- Тесты после каждого урока
- Система уровней и достижений
- Виртуальный портфель с соревнованием (кто заработает больше за месяц)

Сейчас в приложении есть вкладка "Задачи", но она пустая по содержанию. Можно на её основе построить обучающий трек.

### 3.2. Уведомления

- Push-уведомления о значительных изменениях цен (±5% за день)
- Напоминания о дивидендных отсечках
- Еженедельная сводка по портфелю
- Уведомления о завершении обучения модели (для администратора)

### 3.3. Расширение списка тикеров

Сейчас только 5 тикеров из Газпром-группы. Для полноценного приложения нужно:
- Топ-30 акций MOEX (Сбер, Лукойл, Яндекс, Роснефть и др.)
- ETF-фонды (TMOS, SBMX)
- Возможность добавлять тикеры пользователем

### 3.4. Экспорт и отчёты

- Экспорт портфеля и истории сделок в CSV/PDF
- Налоговый отчёт (расчёт НДФЛ по сделкам)
- Сравнение доходности портфеля с индексом MOEX

### 3.5. Интеграция с брокерами

В перспективе — подключение к реальным брокерским API (Тинькофф Инвестиции, Сбер, ВТБ) для:
- Получения реальных котировок в реальном времени
- Синхронизации портфеля
- Совершения реальных сделок (требует лицензирования)

## Технический долг

Помимо новых фич, стоит закрыть следующие технические задачи:

| Проблема | Что сделать |
|---|---|
| CORS `allow_origins=["*"]` | Указать конкретные origins для production |
| `echo=True` в SQLAlchemy | Выключить в production (лишние логи) |
| Нет миграций БД | Добавить Alembic для управления схемой |
| Нет `.env` в репозитории | Есть `.env.example`, но нет валидации при запуске |
| `fillna(method='bfill')` deprecated | Заменить на `df.bfill()` |
| Нет rate limiting на API | Добавить slowapi или аналог |
| Логи только в stdout | Настроить ротацию логов (loguru уже подключен, но не настроен для API) |
| Нет healthcheck для Docker app | Добавить HEALTHCHECK в Dockerfile |
